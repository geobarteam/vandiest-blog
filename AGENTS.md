# vandiest.biz

Geoffrey Vandiest's blog: plain HTML in `site/`, deployed to Azure Static Web Apps (Free) by `.github/workflows/deploy.yml` on a push to `main` or a manual run. No generator, no framework, no database. The design system is Vandiest Pixel: pixels on the chrome, plain type in the prose.

## Rules that never bend

- **Never change the URL of a published post.** The path is the permalink and the canonical URL.
- **Never push on your own initiative.** A push publishes. Only push after the owner says go.
- Every post passes `node tools/check.mjs` before it is committed.

## Layout

```
site/                         web root, uploaded as is
  index.html  archive/        generated by tools/build.mjs, never edit by hand
  rss.xml sitemap.xml search.json   generated
  post/yyyy/mm/dd/slug/index.html   one post, hand-written
  page/<name>/index.html      static pages
  contact/  404.html  robots.txt
  css/site.css                the one stylesheet (Prism theme included)
  js/prism.js                 syntax highlighting, the only script
  fonts/                      self-hosted woff2 (Pixelify Sans, Press Start 2P, Nunito Sans, JetBrains Mono)
  img/yyyy/                   post images; img/site/ holds the pixel illustrations
  files/                      attachments
  staticwebapp.config.json    redirects, headers, 404
templates/post.html           skeleton for a new post ({{placeholders}})
tools/layout.mjs              the shared header, footer and sidebar (single source)
tools/build.mjs               regenerates everything derived from the posts
tools/check.mjs               validates posts and internal links
```

## Commands

```bash
npm ci                         # once
node tools/build.mjs           # regenerate home, archive, feed, sitemap, search; refresh chrome
node tools/check.mjs           # validate the whole site (exit 1 on errors)
node tools/check.mjs <file>    # validate one post
npm run serve                  # http://localhost:3000
```

Run build, then check, before every commit. The build is deterministic: a second run changes nothing.

## Post conventions

1. One post is `site/post/yyyy/mm/dd/slug/index.html`. The path date is the publication date. The slug is lowercase ASCII with hyphens.
2. Complete HTML5: `<html lang>`, `<title>`, `<meta name="description">` (about 150 characters), `<link rel="canonical">` with the full `https://vandiest.biz/post/.../` URL, and `og:title`, `og:description`, `og:url`, `og:type`.
3. Metadata lives in one `<script type="application/ld+json">` block of type `BlogPosting`: `headline`, `datePublished`, `dateModified`, `description`, `keywords` (the tags, at least one), optional `image`. No front matter, no second source of truth. The build rewrites the tag chips from `keywords`.
4. Body: `<main>` > `<article>` > `<header class="post__head">` with the `<h1>` and a `<time datetime>`, then `<div class="post-body">`. Headings inside the body start at `<h2>`.
5. Code is `<pre><code class="language-csharp">` (or `bash`, `powershell`, `xml`, `json`, `javascript`, `sql`, `yaml`), HTML-escaped, one block per snippet, no inline styles.
6. Images are `<img src="/img/yyyy/name.png" alt="..." width height loading="lazy">`, stored in the repo, under 300 KB each. Pixel art gets `class="pixel"`.
7. Links inside the site are root-relative (`/post/.../`), never absolute to vandiest.biz.
8. Asides: `<aside class="callout">` for a tip, `<aside class="callout callout--warn">` for a warning.
9. The regions between `<!-- site:header -->`, `<!-- site:sidebar -->`, `<!-- site:footer -->` and their closing markers are owned by `tools/layout.mjs`. Edit the chrome there, never in a page.

## Design rules (Vandiest Pixel)

- Everything snaps to 4px. No radius, no blur, no soft shadows. Borders are the 4px pixel border.
- Pixelify Sans for headings, Press Start 2P only for short UPPERCASE labels (9 to 10px), Nunito Sans for all running text, JetBrains Mono for code.
- `sky` is the only interactive colour; `sun` is the one accent per region; `grass` and `berry` are status only.
- Day and Night themes follow the reader's system setting.
- The page must read well with CSS disabled. No tracking script, no framework.

## Voice

Direct, first person, sentence case. Short declarative sentences, a concrete scene first, one dry line, no emoji. Headlines make a claim. Buttons say what happens.
